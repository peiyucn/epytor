# Acceptance

> 何时用：用户可见界面/交互/安装/启动流程发生变化，需要证明它真的工作。
> 何时不用：纯内部重构且行为不变；纯文档改动。

> 依赖：[principles/prove-it-works.md](../principles/prove-it-works.md)、[rules/verification.md](../rules/verification.md)、[skills/review/SKILL.md](../skills/review/SKILL.md)

## 步骤

1. **列用例**
   - 正常路径；
   - 至少一个错误/空/加载状态；
   - 权限/禁用状态（适用时）；
   - 刷新、重启、取消、重试（适用时）；
   - 用真实形态的非空数据：真实位数、长文本、边界值。
   - 调用：[principles/prove-it-works.md](../principles/prove-it-works.md)。
   - 证据：用例表（步骤/预期/实际/结果）。

2. **准备环境**
   - 固定提交/构建产物；
   - 记录浏览器/视口/工具版本；
   - 不碰真实用户数据；必要时脱敏。
   - 证据：提交/产物、环境版本。

3. **执行**
   - 按步骤操作，记录预期与实际；
   - UI 看 DOM/文本/URL/控制台/网络；
   - 截图只是证据之一，不是结论；
   - 不伪造截图/DOM/日志。
   - 调用：[rules/verification.md](../rules/verification.md) G8；涉及 UI 时调 [skills/browser/SKILL.md](../skills/browser/SKILL.md)。
   - 证据：截图/DOM/控制台/网络输出。

4. **判断**
   - 实际不符就是失败，不因“整体看起来还行”放过；
   - 失败路径必须有用户可见反馈；
   - 修复后从失败步骤重跑，保留最终证据。
   - 调用：AGENTS C0、C8。

5. **记录**
   - 提交/产物；
   - 环境/工具/视口；
   - 测试数据；
   - 用例表（步骤/预期/实际/结果）；
   - 证据路径；
   - 未验证项、工具限制、剩余风险。
   - 证据：完整记录，可直接复核。

## 输出

```text
提交/产物：
环境/工具：
测试数据：
用例：
证据：
未验证/风险：
```

## 边界

- 工具不可用：明确写“未验证”，不给“应该可以”；
- 只做人工验收：写清操作步骤和预期，不写“已验证”；
- owner 可以豁免 L3，但必须记录理由和剩余风险。

## 停止 / 询问

- 无法启动或构建；
- 需要真实凭据/生产数据；
- 关键路径无法验证；
- 证据可能包含隐私/token。
