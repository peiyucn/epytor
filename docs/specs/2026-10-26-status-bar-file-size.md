# 状态栏显示文件大小

> 状态：已实现（v1.3.0，2026-10-26）｜需求来源：owner 手测反馈「现在大量使用 AI 处理文档，状态栏现在显示字数啥的，能不能把这份文档是多少 K 多少 M 也显示出来」

## 需求范围

在已有的状态栏字数信息**同一行末尾**追加本文件的**磁盘实际大小**，带标签，形如：

```
行(源): 120  字: 3,400  字符: 8,900  大小: 12.3 KB
```

## 口径（core decision）

**「大小」= 磁盘上该文件的字节数**（`vscode.workspace.fs.stat().size`），不是编辑器里当前内容的字节数。

理由：需求背景是「大量使用 AI 处理文档」——AI 工具读写时真正搬运的是盘上那份文件；
这也是资源管理器里看到的数。用「当前内容实时字节数」会得到一个用户在别处看不到的数，
且改了字没保存也会变，反而容易误判。

## 显示格式

| 范围 | 格式 | 示例 |
| :--- | :--- | :--- |
| < 1024 B | `N B`（整数） | `980 B` |
| < 1024 KB | `X.Y KB`（一位小数） | `12.3 KB` |
| ≥ 1024 KB | `X.Y MB`（一位小数） | `2.4 MB` |

* 单位用 `B` / `KB` / `MB`（1024 进制），与 VS Code 资源管理器的显示口径一致；
* 标签文案走 l10n：英文 `Size: {0}`、中文 `大小: {0}`；
* 数值部分用 `.toFixed(1)`，但 `KB` 档若恰好整千（如 `8.0 KB`）仍保留一位小数，避免宽度跳动。

## 交互边界

1. **何时刷新**：`_refreshStatusBar()` 是唯一出口，沿用其既有触发点（面板激活/失活、wordCount 消息到达、打开文件）。
2. **文件大小何时取**：在 `ready`（面板初始化）时 `stat` 一次并缓存；保存成功（`_saveNow`）后、以及**外部变更被处理时**（采纳盘上内容 / 保留用户内容两条分支）再 `stat` 更新缓存。
   不在每次 `wordCount` 消息里 stat——打字时每条消息都走一次 fs 会白费 I/O。
   「外部变更」这条触发点是需求场景的核心（AI 工具批处理文档），漏掉它状态栏会一直显示外部改动前的旧值（实测过：盘上 16.4 KB → 42.2 KB，状态栏仍停在 16.4 KB）。
3. **读不到文件时**（OneDrive 占位符、文件被删/移动、权限不足）：**不显示大小**（该段整体省略），
   字数部分照常显示。不显示 `0 B` 或 `?`，避免误导。
4. **文件不存在 / 尚未落盘**（新建未保存的文档）：同上，省略大小段。
5. **面板失活**：状态栏本来就在失活时隐藏，无需额外处理。
6. **不出现的位置**：不新增第二个状态栏项（owner 明确要同一行）。

## 验收标准

1. 打开任意 `.md`，状态栏显示 `行(源): N  字: N  字符: N  大小: X`，四段齐全；
2. 用外部工具把该文件改大（如追加 100 KB 文本），触发外部变更重建后再看：大小已更新（实测：16.4 KB → 42.2 KB 自动跟上）；
3. 编辑器内打字不改变大小（未保存），`Ctrl+S` 后大小与盘上一致；
4. 打开一个 OneDrive 未下载的占位文件（或把文件删掉后重建面板）：字数照常、**大小段消失**，不出现 `0 B`；
5. 中文界面显示「大小:」，英文界面显示「Size:」；
6. 新建一个未保存的 untitled 文档：不显示大小，不崩。

## 不做

* 不做「当前内容实时字节数」（口径已定，见上）；
* 不做单独的第二个状态栏项（owner 要求同一行）；
* 不做点击状态栏跳转/弹出明细。
