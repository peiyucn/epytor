## 为什么只剩这么几条

这次升级里真正会改变编辑器行为的只有两处，其余都已被自动化测试盖住：

| 已排除的疑虑 | 怎么排除的 |
| :--- | :--- |
| 行内公式前多出的不可见 `<img class="ProseMirror-separator">` 会不会破坏布局 | 实测它落在 `<p>` 内部，被 `:first-child` 选中的仍是最外层 `<p>`；且自带 `!important` 的 `display:inline`/`margin:0` 防护，已核对该规则进了产物 CSS |
| 这个分隔符会不会被当成图片塞进保存的 Markdown | 序列化往返仍是 `$x$` |
| katex 版本会不会退回有漏洞的版本 | `katexCompat.test.ts` 版本守卫，低于 0.18.2 直接失败 |

以上都在 `webview/__tests__/inlineAtomSeparator.test.ts` + `katexCompat.test.ts` 里。**jsdom 有 DOM 树但没有布局引擎**——它能证明结构和规则对，量不了像素和手感。所以下面这块只能由你在真机看。

## 需要你验的（5 条）

准备一个 `.md`，把下面这段贴进去：

```Markdown
$x$ 开头的段落

| 列A | 列B |
| --- | --- |
| $x$ 说明 | 普通 |

$$\frac{1}{2}$$

$\frac{1}$
```

$x$开头的段落

| 列A     | 列B |
| :----- | :- |
| $x$说明 | 普通 |

$\frac{1}{2}$

$\frac{1}$

* [x] **首行公式的光标**——光标放在 `$x$` 开头那一行，左右方向键能跨过公式、能正常点进去编辑
* [x] **首行公式按退格**——光标在公式最前面按 Backspace，不崩、不吞掉公式
* [x] **视觉间距**——首行公式那行、和表格里 `$x$ 说明` 那一格，**顶部没有莫名多出的空隙**（这条是 jsdom 唯一量不了的）
* [x] **中文输入法**——在公式旁边起笔打中文，不丢字、不跳位
* [x] **出错公式的降级**——上面 `$\frac{1}$`（故意写错）显示为红字提示，**不崩、不白屏**
* [x] **公式编辑弹框不被其他元素遮挡**
* [x] **表格内的行内公式可以修改**
* [x] **行内公式编辑框样式与其他编辑框统一**

只要这 8 条过，本版就可以发。

## 明确不用测的

以下是本版**没有改动**的东西，不必再过一遍：

* 保存保真（未编辑保存逐字不变）—— v1.2.5 的修复，本版没碰，`saveFidelity.test.ts` 10 条用例已覆盖
* 任务列表回车、目录面板、标题吸顶、代码块高亮 —— 同上，无改动
* 粘贴 / 拖拽 —— `prosemirror-view` 确实改过这些路径（1.42.3 的 XSS 修复），但都是内部校验加固，正常粘贴行为不变；除非你想额外确认，不必列入必测
* mermaid 图 —— mermaid **自身版本没动**（仍 11.16.1）；`dompurify` 默认允许标签表完全一致，只新增放行两个 SVG 属性（`pointer-events`、`vector-effect`），属放宽而非收紧，现有图不受影响。（注：`mermaidZoom.test.ts` 只覆盖缩放逻辑，不覆盖 mermaid 渲染本身——上面这条判断依据是依赖版本与标签表的对比，不是测试。）
